# RAG Answer — ответ по базе знаний

| Поле | Значение |
|---|---|
| Название | RAG Answer |
| Версия | 1.0.0 |
| Статус | черновик: после рефакторинга на модели не прогонялся |
| Владелец | @yagitpa (Яков Пальчиков) |
| Теги | rag, knowledge-base, support, ru |
| Модель | gpt-3.5-turbo, как в проекте PEr06. Меняется в настройках проекта, промпт от модели не зависит |
| Файлы | `system.md` — системный промпт, `user.md` — пользовательское сообщение, `CHANGELOG.md` — история версий |

## Цель

Ответить на вопрос пользователя строго по найденным фрагментам документов: полностью, частично или честным отказом. Каждый ответ ссылается на файлы, из которых взяты факты. Отказ выдаётся фиксированной фразой, чтобы код мог его распознать.

## Когда использовать и когда нет

Подходит для ассистентов по регламентам, FAQ, конспектам и любой базе, где важнее не ошибиться, чем ответить на всё.

Не подходит, если ассистент должен дополнять ответ общими знаниями, вести свободный диалог или отвечать на приветствия: такие вопросы шаблон отправит в отказ.

## Переменные

| Переменная | Когда меняется | Значение в PEr06 |
|---|---|---|
| `{{KNOWLEDGE_BASE}}` | при внедрении | правила сервисной службы и FAQ по продукту |
| `{{ANSWER_LANGUAGE}}` | при внедрении | русский |
| `{{MAX_SENTENCES}}` | при внедрении | 4 |
| `{{SOURCE_LABEL}}` | при внедрении, из той же константы, что и сборка контекста в коде | Источник |
| `{{REFUSAL_TEXT}}` | при внедрении, из той же константы, что и `is_refusal()` | В предоставленных документах нет информации для ответа на этот вопрос. |
| `{{MODE}}` | при запуске | прод |
| `{{CONTEXT}}` | в каждом запросе | фрагменты с пометками `[Источник: <файл>]` |
| `{{QUESTION}}` | в каждом запросе | вопрос пользователя |

Подстановка заменой строк `{{ИМЯ}}`, не через `str.format()`: во фрагментах документов бывают фигурные скобки.

## Пример входа и выхода

Вход, пользовательское сообщение:

```
Контекст:
[Источник: doc2.txt]
На базовом тарифе разрешено не более трёх одновременных сессий. При превышении лимита самая старая сессия завершается автоматически.

Вопрос: Сколько устройств можно использовать одновременно на базовом тарифе?
```

Ожидаемый выход, режим «прод»:

```
На базовом тарифе можно использовать не более трёх одновременных сессий. Если лимит превышен, самая старая сессия завершается автоматически.
Источник: doc2.txt
```

Текст фрагмента в примере сокращён. Для прогона берётся настоящий чанк из `data/doc2.txt`.

## Тест-кейсы

По одному на каждую ветку. Вопросы взяты из тестового набора PEr06, третий составлен из тех же документов. Для проверки ветки удобно запускать в режиме «отладка».

### T1. Ветка ОТВЕТ, вопрос другими словами

Вопрос: «Не получается зайти в личный кабинет, пароль не помню - как быть?»
Контекст: чанк из раздела `doc2.txt` «Как восстановить доступ к аккаунту».
Что проверяет: ветка выбирается по смыслу. Слов «личный кабинет» и «не получается зайти» в документе нет.

Тест пройден, если:
- в режиме отладки первая строка содержит `ветка: ОТВЕТ`;
- в ответе есть ссылка «Забыли пароль?», письмо на почту из регистрации и срок 10 минут, без округления;
- последняя строка ровно `Источник: doc2.txt`;
- ответ не короче одного шага и не длиннее 4 предложений или короткого нумерованного списка.

### T2. Ветка ОТКАЗ, правдоподобный контекст без нужного факта

Вопрос: «Сколько стоит премиум-подписка в месяц?»
Контекст: чанки `doc2.txt` про премиум (безлимит сессий, приоритетная поддержка). Цены в них нет.
Что проверяет: модель не выдумывает сумму, даже когда контекст похож на подходящий.

Тест пройден, если:
- в режиме «прод» весь ответ совпадает со строкой `{{REFUSAL_TEXT}}` посимвольно;
- в ответе нет строки источника, цифр и названий валют;
- `is_refusal()` возвращает `True`.

### T3. Ветка ЧАСТИЧНЫЙ

Вопрос: «Сколько устройств можно подключить на базовом тарифе и сколько он стоит?»
Контекст: чанк `doc2.txt` про одновременные сессии.
Что проверяет: подтверждённая часть выдаётся, недостающая называется прямо и не додумывается.

Тест пройден, если:
- в режиме отладки первая строка содержит `ветка: ЧАСТИЧНЫЙ`;
- в ответе есть «не более трёх одновременных сессий»;
- есть отдельная строка, начинающаяся с `В документах нет:` и упоминающая стоимость;
- в ответе нет сумм и валют;
- последняя строка ровно `Источник: doc2.txt`.

## Правила использования

1. Текст промпта правится только через pull request. Прямые коммиты в основную ветку не делаются.
2. Каждое изменение повышает версию и получает запись в `CHANGELOG.md`: major, если меняются ветки или формат выхода; minor, если добавлена переменная или правило без поломки старого поведения; patch, если исправлена опечатка или формулировка.
3. Перед слиянием все три тест-кейса прогоняются на новой версии, результат прикладывается к pull request.
4. Если меняется `{{REFUSAL_TEXT}}` или `{{SOURCE_LABEL}}`, в том же pull request меняются константы в коде. Иначе код перестанет распознавать отказ и источники.
5. Ревью делает владелец карточки.
